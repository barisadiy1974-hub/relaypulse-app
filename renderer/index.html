Nyx = a curses-based full-screen monitor for the anon relay (bandwidth, connections, circuits, config, logs). In the sandbox build, this button opens the embedded terminal and ssh -tt <server> nyx -s /run/anon/control on the selected server. In the terminal: m = menu, l = logs, c = circuits, ←/→ = pages, q = quit.

Requirement: nyx must be installed on the server (apt install nyx) and the /run/anon/control socket must be reachable (the anon service must be running). The sandbox build does not require sshpass.

htop = interactive process/CPU/RAM viewer. In the sandbox build it runs in the embedded terminal: ssh -tt <server> htop on the selected server. In the terminal: F5 = tree view, F6 = sort column, F9 = kill, q = quit.

Requirement: htop must be installed on the server (apt install htop -y). Falls back to top automatically if not installed. The sandbox build does not require sshpass.

Reads/writes the selected server's /etc/anon/anonrc file over SSH. Save + Restart runs anon --verify-config after writing; on error it restores from .bak and does not restart the service. Apply bandwidth preset adds the BandwidthRate 10 MBytes / Burst 15 MBytes / AccountingMax 4 TBytes / month 1 00:00 block to the selected server and restarts it. Apply preset to ALL applies the same setting to all servers (careful: cannot be undone).

Connection Mode

          
          
HTTPS: used if an agent is installed on the server. SSH: works safely on any device, no token issues. Once saved, all relays connect using this mode.


          
Polling

          
          
          
          
          
          
Retry: how many times SSH re-tries a connection per poll. Timeout: max seconds for one poll (0 lets RelayPulse pick based on interval). Heartbeat: after this many consecutive failed polls a relay card turns red (before that it stays yellow "stale"). Applied live on Save.


          
What counts as "up"

          
          
          
Machine health — reachability, CPU, memory, disk, network, uptime — is read the same way on every Linux server. This is only about which service RelayPulse should check with systemctl is-active. Separate several names with spaces; the first one that is not inactive wins. Instances (name@something) and numbered units (name1, name2) are found automatically. If no name matches, a machine listening on one of these ports still counts as up. Leave both empty to keep the defaults.

Security

          
Fleet-wide SSH hardening. Checks each server's fail2ban status + banned IPs, SSH password-auth, MaxStartups, and port. "Harden" installs fail2ban + sets MaxStartups/LoginGraceTime + (for key-based logins) disables password-auth. Only touches SSH/port 22 — never relay ports (9001/443/80). Protects against SSH-flood freezes.

Agent certificates

          
Agents use self-signed certificates, so RelayPulse remembers each agent's certificate the first time it answers and refuses anything else — otherwise a machine on the network in between could collect your agent tokens. Reset only after reinstalling an agent; the next poll learns the new certificate.

AI Auto-Fix

          
          
Choose when AI Auto-Fix acts. "Fix automatically" runs the chosen command on the server. "Ask me before running" picks the command and puts it in an approval queue with the evidence behind it — nothing runs until you approve. "Diagnose only" picks a command and logs it but never touches the server. "Disabled" turns the feature off.

          
          
          
          
          
          
The API key is stored separately in an encrypted vault on disk. It stays hidden by default; you can reveal and copy it.

About

          

            
This window

            

          

          
Each tick runs a single SSH command per server (/proc/net/dev, ss, /proc/stat, /proc/meminfo, df, systemctl is-active anon). Rates are computed by diffing byte counters between ticks. Logs come from journalctl -u anon or /var/log/anon/*.

          
        

      

      

        

          
Help

          
RelayPulse reads your servers over SSH, or over the optional metrics agent. Nothing runs on a server of ours and no account is created. The iPhone app works the same way.


          
First steps

          
    
            
  1. Add a server. Settings › Server Connections › + Add Server. Give it a name and its IP address or hostname.
    2. 
            
  2. Choose how RelayPulse logs in. Type the server's Password — for a VPS, the root password your provider sent you. Or use an SSH key, which is safer:
              click Import SSH key under the server list (one key for all servers).
              put the key file's path in SSH key, or leave it empty to use ~/.ssh/id_ed25519.
    3. 
            
  3. Save Relay, then Test connection to check the login straight away.
    4. 
            
  4. Watch. On the Servers tab the card turns green, yellow or red after the next reading.
    5. 
            
  5. Optional: the HTTPS agent. Click Install in the Agent column, or Install HTTPS Agent on all. It makes its own token — nothing to type. Then Settings › Monitoring › Connection type › HTTPS Agent.
    6. 
          


          
Server fields

          

            
Relay name
Any label you like. It is what the cards and alerts show.

            
Host or SSH alias
The server's IP address or hostname. An alias from ~/.ssh/config also works.

            
User / Port
Usually root and 22. Change them only if your server uses something else.

            
SSH key
Path to a private key file. Empty: ~/.ssh/id_ed25519 or your ssh config.

            
Password
The server's login password, stored encrypted on this computer.
              The imported key is tried first, then the password.
              When set it is used instead of the key, and it needs sshpass installed.

            
Anon instance
Only for Anyone relays, when one IP address runs two relays. Otherwise leave it empty.

            
Agent column
Install puts the agent on that server over SSH; 🟢 Agent means it is running — click it to remove.

            
Import SSH key
One private key (ed25519 or RSA, no passphrase) for all servers, kept in the encrypted vault. ~/.ssh is not read.

            
Save Relay / Save Connections
Both save the whole server list. Monitoring picks up the change at once.

Settings › Monitoring

          

            
Connection type
SSH works on every server with nothing installed. HTTPS Agent is faster and lighter on large fleets, but needs the agent on each server. Applies to all servers.

            
Interval (ms)
How often each server is read, in milliseconds: 120000 is two minutes, 30000 (30 seconds) is the lowest.

            
Default log lines
How many log lines the log views load.

            
Retry count
How many times one reading retries the SSH connection (1–3).

            
Timeout
The longest one reading may take, in seconds. 0 lets RelayPulse choose.

            
Heartbeat threshold
How many failed readings in a row turn a server red. One fewer shows yellow. A single miss stays green — short network hiccups are common and are not outages.

            
What counts as "up"
Which service to check on each server, e.g. nginx or docker — separate several with spaces. Ports: if none of those services exists, a server listening on one of these ports still counts as up. Leave both empty for the defaults.

            
Live Monitoring Preview
How many servers are online, yellow and red right now, and the average response time.

            
Alarm
A sound when a server goes offline, repeated every few minutes while it stays offline. Test alarm plays it once.

            
Low RAM warning
When a server's memory use passes this percentage, its card shows a Low RAM warning — a heads-up before the box freezes.

            
iPhone
Export for iPhone saves the server list with agent ports and tokens for the iPhone app's Import. Passwords and SSH keys are not exported — add them on the phone.

            
Test connection
Runs one reading on the chosen server and shows exactly what came back.

          


          
Settings › Security

          

            
Scan All Servers
Reads fail2ban, banned IPs, password login and SSH limits on every server. Changes nothing.

            
Harden Risky Ones
Installs fail2ban and tightens SSH limits. On servers you reach with a key it also switches password login off — check that the key works first. Servers you log in to with a password keep it. Relay ports are never touched.

            
Agent certificates
RelayPulse remembers each agent's certificate and refuses a different one. Reset only after reinstalling an agent.

What the colours mean

          

            
Online
Reachable, and the watched service is running.

            
Warning / Stale
Reachable but the service is not active, or a few readings were missed — usually a network hiccup.

            
Offline
Readings failed as many times in a row as the Heartbeat threshold. This one is real.

          

          
Zero connections is not an error: the server is running and simply has no traffic yet.


          
When a server will not connect

          

            
Password refused
Wrong password, password login switched off on the server, or it only allows keyboard-interactive login. Use an SSH key instead.

            
Authentication refused
The key is not in the server's /root/.ssh/authorized_keys (for root), or it belongs to another user.

            
Timeout
Usually the wrong SSH port or a firewall.

            
Worked, then stopped
fail2ban on the server banned this computer's address after repeated failures. It lifts by itself after a while.
